# 内容收集 · LLM Wiki 模式

把用户丢来的链接，**织进一个越用越密的知识网**，而不是堆一堆互不相干的剪报。这是 opennote 的看家本事——用微信收链接，本地织笔记。

方法论（Andrej Karpathy 的 LLM Wiki）：**把 LLM 当编译器**。原始资料是源代码（`raw/`，存进去就不再改），wiki 是编译产物（`wiki/`，你来写和维护）。每个概念一页、页页用 `[[wikilink]]` 互连，时间越久这张网越值钱。

> 下面命令里的 `<skill>` 指本 SKILL.md 所在目录（skills 菜单里有它的绝对路径），脚本在 `<skill>/scripts/extract.mjs`。所有相对路径按 cwd（`~/.opennote/notes/`）解析，父目录自动建。

## 目录结构

```
raw/                       # 不可变原文，一个源一个文件，存进去不再改
  .html/                   # browser 落盘的中间 HTML，extract 用完即可忽略
wiki/
  summaries/   <slug>.md   # 摘要页：一个源一页
  concepts/    <slug>.md   # 概念/框架页：一个概念一页
  entities/    <slug>.md   # 实体页：人 / 工具 / 组织 / 产品
  syntheses/   <slug>.md   # 跨页综合（一般不建，留给提问/回顾时生成）
  index.md                 # 全库索引
  log.md                   # ingest 流水
```

## Ingest 流程（收一个链接 = 跑这一套）

> 目录骨架（`raw/`、`wiki/{summaries,concepts,entities,syntheses}/`、`index.md`、`log.md`）启动时已建好，只管往里 write。读某个具体概念页读到 not-found 是正常的，读不到就新建。

直接动手，按顺序来，别长篇规划：

1. **抓 HTML + 抽正文存原文（raw）**。两步，文件名都由工具/脚本自动生成，**你不用猜 slug**：

   a. `browser` 抓页面，HTML 落到中间目录——`save_to` 给目录、**以 `/` 结尾**，工具按 URL 自动命名，只回元信息、HTML 不进上下文：
      `browser(url, save_to="raw/.html/")`
      它会返回实际落盘的 `.html` 路径，记住它。

   b. 跑 extract 把那个 HTML 抽成 markdown 并存进 `raw/`（脚本**按真实标题命名文件、自己写盘**）：

      ```bash
      node <skill>/scripts/extract.mjs <上一步返回的 .html 路径> --save raw --date {YYYY-MM-DD}
      ```

   - extract 会把「存到哪」打到 stderr（如 `已存 raw/2026-06-02-真实标题.md`），**用那个路径**填摘要页的 `raw:` 字段和索引，别自己另编文件名。
   - 干净 markdown 同时打到 stdout，你在上下文里能看到，供下一步写摘要用。
   - **raw 是源代码，存进去之后任何环节都不许改它。**

   > ⚡ 性能铁律：**已经在磁盘 / stdout 上的大段内容，落盘搬运一律用脚本 / bash（`--save`、`>`、`cp`），绝不用 `write` 工具重打一遍。** `write` 的内容是模型当参数重新生成的，几千字正文会让模型吐上万 token、卡好几分钟。`write` 只用来写你**新写的、短的**内容（摘要页、概念页、索引）。摘要页、概念页本身也要短——慢模型下，`write` 的总字数直接决定这条消息要等多久。

2. **写摘要页**：文件名**直接复用 raw 的**——extract 已按标题命名好（如 `raw/2026-06-06-标题.md`），摘要就写同名 `wiki/summaries/2026-06-06-标题.md`，别自己重新 slug（模型手搓 slug 容易把标点、空格全塞成一串 `-`）。`write` 它（格式见下），提炼这篇在讲什么，并用 `[[wikilink]]` 指向涉及的概念/实体页。要点**提炼成短句**，不是把原文段落搬过来（原文在 raw，要细节就 read 它）。

3. **建概念 / 实体页**：从内容里挑**最多 2 个**最值得单独成页的概念/实体，每个 `write` 一页（紧凑格式见下），只讲一个概念，写清是什么 + 为什么重要，并 `[[链接]]` 到相关页。每页**写紧凑**（2-5 条短句就够），别把原文整段复述进来。
   - **查重（库里已有内容时才做）**：判断某概念**可能之前收过**，先 `read` 那页；读到了就把新信息**整合进去**（追加要点、在「来源」区加回链、矛盾记到「分歧」区，别覆盖）；读不到就新建。**空库或拿不准时直接新建**，别为查重反复 read。

4. **更新索引和流水**：`read wiki/index.md` 拿现有列表，把新建的页加进去再 `write` 回；`read wiki/log.md` 后在末尾追加一行（日期 + 源 + 动了哪些页）再 `write` 回。两个文件已存在，是增量更新不是新建。

5. **报告**：一句话——收了什么、建/更新了哪几页。所有 `write` 成功前不要说"已保存"。

链接用页面标题（Obsidian 风格 `[[标题]]`），opennote 笔记天然兼容 Obsidian vault。

## 摘要页格式

```markdown
---
title: <原标题>
type: summary
source: <原始 URL>
raw: raw/<YYYY-MM-DD>-<slug>.md
author: <作者，没有省略>
date: <发布日期 YYYY-MM-DD，没有省略>
collected: <收集日期 YYYY-MM-DD>
tags: [<2-4 个标签>]
---

# <原标题>

> <一句话概括，20-40 字>

## 要点

- <3-6 条核心观点，提炼不是摘抄>

## 涉及

- [[<概念页标题>]] — <一句话说这篇怎么用到它>
- [[<实体页标题>]] — <…>

## 原文

[raw/<YYYY-MM-DD>-<slug>.md](raw/<YYYY-MM-DD>-<slug>.md)
```

## 概念 / 实体页格式（紧凑版，够日常用）

```markdown
---
title: <概念名 / 实体名>
type: concept        # 实体页写 entity
tags: [<2-4 个>]
---

# <名>

> <一句话定义>

## 是什么 / 为什么重要

- <2-5 条>

## 关联

- [[<相关页>]] — <什么关系>

## 来源

- [[<摘要页标题>]]
```

> slug / 命名细则、synthesis 页、矛盾「分歧」区写法见 `references/wiki-schema.md`——**拿不准再读，不必每次读。**

## 为什么这样做

- **raw 不可变**：源是编译的输入，改了源整张 wiki 就失真。要修订认识，改 wiki 页，不动 raw。
- **一页一概念**：稠密的单概念页才连得出好链接、答得出好问题。一页塞十个概念，等于没有页。
- **整合而非堆叠**：第二次遇到同一个概念，是去**长**已有那页，不是再开一篇。这才叫"织"，知识才会复利。
- **记矛盾不抹平**：两个源说法冲突，价值恰恰在这个冲突里，留着它。
- **wikilink 即图谱**：链接多了，wiki 自己长成知识图谱；且与 Obsidian 互通。

## 边界情况

- **抓不到 / 是空壳**（登录墙、付费墙、纯 JS 站）：extract 会报「Readability 提取正文失败」。如实说抓不到，**别编造内容**填页，可建议 `open(url)` 让用户自己看。
- **链接是首页/列表页不是单篇**：跟用户确认收哪篇，别抓一堆导航文字。
- **一次多个链接**：逐个跑完整 ingest。
- **同一个源已收过**（`raw/` 里同名已存在）：先 `read` 看，问用户是更新还是跳过。
- **内容太单薄不值得拆概念**：只存 raw + 摘要页，不硬抽概念。
- **视频站**（B 站等）：`browser` 只拿到页面元数据，口播不在网页里，交给 `parse-bilibili`。
