# 内容收集 · LLM Wiki 模式

把用户丢来的链接，**织进一个越用越密的知识网**，而不是堆一堆互不相干的剪报。这是 opennote 的看家本事——用微信收链接，本地织笔记。

方法论（Andrej Karpathy 的 LLM Wiki）：**把 LLM 当编译器**。原始资料是源代码（`raw/`，存进去就不再改），wiki 是编译产物（`wiki/`，你来写和维护）。每个概念一页、页页用 `[[wikilink]]` 互连，时间越久这张网越值钱。

## 目录结构

所有路径相对 cwd（`~/.opennote/notes/`），父目录自动创建：

```
raw/                       # 不可变原文，一个源一个文件，存进去不再改
wiki/
  summaries/   <slug>.md   # 摘要页：一个源一页
  concepts/    <slug>.md   # 概念/框架页：一个概念一页
  entities/    <slug>.md   # 实体页：人 / 工具 / 组织 / 产品
  syntheses/   <slug>.md   # 跨页综合（本 skill 一般不建，留给提问/回顾时生成）
  index.md                 # 全库索引
  log.md                   # ingest 流水
```

## Ingest 流程（收一个链接 = 跑这一套）

> **目录结构已经初始化好了**：`raw/`、`wiki/{summaries,concepts,entities,syntheses}/`、`wiki/index.md`、`wiki/log.md` 都已存在（opennote 启动时建好）。你只管往里 write。具体页面是否已存在另说——`read` 某个具体概念页读不到 not-found 是正常的，读不到就新建。

直接动手，按顺序 write，别长篇规划：

1. **抓 + 同时存原文**：调 `fetch_content(url, save_to="raw/{YYYY-MM-DD}-{slug}.md")`。它会**把正文原样直接写进 raw 文件**（自动建目录），同时把内容返回给你用于后面写摘要/概念页。**存的是源代码，之后任何环节都不许改它。**

   > ⚡ 性能铁律：存大段原文一定用 `fetch_content` 的 `save_to`（或对脚本输出用 shell 重定向）。**绝不要把抓到的正文返回后再用 `write` 工具写一遍**——`write` 的内容是模型当参数重新生成的，几千字正文会让模型吐上万 token、卡好几分钟。`write` 只用来写你新写的、短的内容（摘要页、概念页、索引）。
3. **写摘要页**：`write wiki/summaries/{slug}.md`（格式见下），提炼这篇在讲什么，并用 `[[wikilink]]` 指向它涉及的概念/实体页。
4. **建概念 / 实体页**：从内容里挑 3-8 个值得单独成页的概念和实体，每个 `write` 一页（格式见 `references/wiki-schema.md`），只讲一个概念，写清是什么 + 为什么重要，并 `[[链接]]` 到相关页。
   - **查重（库里已有内容时才做）**：如果你判断某个概念/实体**可能之前收过**，先 `read` 那一页；读到了就把新信息**整合进去**（追加要点、在「来源」区加回链、矛盾记到「分歧」区，别覆盖）；读不到就新建。**空库或拿不准时直接新建**，不要为查重反复 read。
5. **更新索引和流水**：`read wiki/index.md` 拿到现有列表，把新建的页加进去再 `write` 回；`read wiki/log.md` 后在末尾追加一行（日期 + 源 + 动了哪些页）再 `write` 回。两个文件已存在，是增量更新不是新建。
6. **报告**：一句话——收了什么、建/更新了哪几页。所有 `write` 成功前不要说"已保存"。

链接用页面标题（Obsidian 风格 `[[标题]]`），opennote 笔记天然兼容 Obsidian vault。

> 概念/实体/索引/流水页的**详细格式和命名规则**见 `references/wiki-schema.md`，建页前读一次即可。

## 摘要页格式（最常用，内联在这）

```markdown
---
title: <原标题>
type: summary
source: <原始 URL>
raw: raw/<YYYY-MM-DD>-<slug>.md
author: <作者，没有省略>
date: <发布日期 YYYY-MM-DD，没有省略>
collected: <收集日期 YYYY-MM-DD>
tags: [<2-4 个标签>]
---

# <原标题>

> <一句话概括，20-40 字>

## 要点

- <3-6 条核心观点，提炼不是摘抄>

## 涉及

- [[<概念页标题>]] — <一句话说这篇怎么用到它>
- [[<实体页标题>]] — <…>

## 原文

[raw/<YYYY-MM-DD>-<slug>.md](raw/<YYYY-MM-DD>-<slug>.md)
```

## 为什么这样做

- **raw 不可变**：源是编译的输入，改了源整张 wiki 就失真。要修订认识，改 wiki 页，不动 raw。
- **一页一概念**：稠密的单概念页才连得出好链接、答得出好问题。一页塞十个概念，等于没有页。
- **整合而非堆叠**：第二次遇到同一个概念，是去**长**已有那页，不是再开一篇。这才叫"织"，知识才会复利。
- **记矛盾不抹平**：两个源说法冲突，价值恰恰在这个冲突里，留着它。
- **wikilink 即图谱**：链接多了，wiki 自己长成知识图谱；且与 Obsidian 互通，用户随时能在 vault 里打开。

## 边界情况

- **抓不到 / 是空壳**（登录墙、付费墙、纯 JS 站）：如实说抓不到，**别编造内容**填页。可建议 `open_path(url)` 让用户自己看。
- **链接是首页/列表页不是单篇**：跟用户确认收哪篇，别抓一堆导航文字。
- **一次多个链接**：逐个跑完整 ingest。
- **同一个源已收过**（`raw/` 里同名已存在）：先 `read` 看，问用户是更新还是跳过。
- **内容太单薄不值得拆概念**：那就只存 raw + 摘要页，不硬抽概念。
